    Where the Context Graph earns its place

    The Context Graph is most useful when the answer is a relationship, not something you can find by opening a file. Across three models and seven scored prompts it improved accuracy in 18 of 21 prompt-model pairs.

    Where it earned its place

    • Runtime calls. The service builds the destination URL at startup, so no repository records the full relationship.
    • HTTP endpoints. It found 48 services with no repository in the checkout, each straight from the graph's results, not from the model trying to remember a public project.
    • API callers. Opus found 12 of the 13 real callers (9 alone) and returned 30 services instead of 54. It was guessing less.

    Cheaper too, and where it helped less

    For two of the three models these questions also got cheaper:

    −27%Opus cost
    −20%GPT-6 Astra cost

    When the answer was already sitting in a file, the model was often better off reading that file without the graph.

    Answer already written in a repository?
    Simply read the files.
    Answer lives between repositories, services and systems?
    That is where the Context Graph earns its place.

    The api-discovery skill

    The Postman plugin picks the source by the question. For consumers, ownership and change impact, that source is the Context Graph.

    Claude Code · Postman plugin

    > Who consumes the platform's HTTP API, and what breaks if I change it?

    ● Skill(postman:api-discovery)

    ⎿ Picks the source by the question: consumers and change impact → Context Graph

    ● postman · submitContextGraphAsk (MCP)

    ⎿ query: "Which services call the platform's HTTP API, and what are their upstream and downstream dependencies?"

    ⎿ returns an askId, status: pending

    ● postman · getContextGraphAsk (MCP)

    ⎿ polled until status is completed, then reports the answer with its citations

    Then verify. The skill reports the source, the evidence and the gaps

    • Coverage depends on what's connected and ingested. Verify consequential leads against definitions, source or telemetry.
    • A newly added call may not be there yet. The graph refreshes; your last commit may be newer.
    • The team comes from the API key, not the repo's workspace binding. Changing the binding can't fix a query against the wrong organization.
