Two readers, same content

One page. Two very different readers.

BEFORE

One reader

An HTML/JS website built for a human: skimming headings, scanning for one paragraph.

No second reader existed — developers read the docs and wrote the integration themselves.

→
NOW

Two readers

A human still skims. But now an agent has to discover, authenticate, parse, and recover from errors on its own.

This is dual readership: the same page, read by two very different readers.

The agent-facing surface

What we create for agents.

01

llms.txt

A plain-text index at the root of the site, so an agent knows what exists before it starts guessing.

02

Per-page Markdown

The same content as the HTML page, stripped of navigation and JS chrome, so it is cheap to parse.

03

An MCP server

A tool the agent calls directly, like searchDocs, instead of scraping and re-parsing pages itself.

Key takeaway Three formats, one purpose: give the agent a shortcut past the parts of the page it cannot use. Nobody has time to hand-write and maintain three more artifacts.
