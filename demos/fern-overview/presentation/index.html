01 · Patterns

Four ways agents call your API

Every one of them reads from the same two things — your documentation and your spec. If either is unreliable, all four fail the same way.

PATTERN 01

Direct REST / GraphQL

The agent constructs HTTP requests straight from documentation context.

GET /v1/plants/<id>
PATTERN 02

Function calling

The model picks a tool definition; the framework executes the call.

tools=[get_weather, ...]
PATTERN 03

Model Context Protocol

A standardized discovery layer any MCP-compatible agent can connect to.

mcp://server/tools
PATTERN 04

Generated CLI

Every endpoint becomes a wrapper an agent can run from a shell.

acme plants get --id 001

01 · The gap

Two things break today

Neither is exotic. Both are the default state of almost every public API on the internet.

🔎

Discovery

Docs aren't built for machines
  • Navigation menus, JavaScript, and CSS burn the token budget before an agent ever reaches an endpoint description.
  • No standard answer to “what APIs exist here, and what do they do?”
  • Crawlers see marketing chrome. Agents need the technical reference.
🔁

Reliability

SDKs drift from the spec
  • Hand-written SDKs introduce breaking changes an agent cannot recover from.
  • Inconsistent error handling, auth flows, and response shapes across languages.
  • Bad docs in → wrong code out. Developers ship slower; agents fail silently.

02 · Agent-readability

Generated, not retrofitted

Three surfaces, rebuilt on every docs build. There is no scraper to maintain, no vector database, no RAG pipeline drifting out of sync.

llms.txt

A markdown index of every page in the portal — guides, reference, changelogs. One fetch tells an agent what exists.

llms-full.txt

Full body content embedded. Agents parse the whole portal in a single fetch instead of crawling it page by page.

<any-page>.md

Append .md to any URL and get the same page without the chrome — the technical substance, inside the token budget.

Covers the whole portal — not just the API reference Strips nav and marketing chrome — keeps the substance Rebuilt every deploy — it cannot go stale

02 · Agent infrastructure

Type-safe SDKs are agent infrastructure

Auth, retries, and pagination belong in the client — not in the prompt.

What agents need

  • Deterministic interfaces, not hand-rolled HTTP.
  • Predictable shapes — correct types, required fields, and error structures fixed at generation time.
  • Multi-language parity — a Python agent and a TypeScript agent behave identically.
  • Auth, retries, pagination handled by the SDK — not improvised by the model.

What Fern delivers

  • Auto-generated SDKs with full type coverage, auth, retries, and pagination.
  • Custom code coexists with generated code — layer business logic without forking.
  • Spec change → PR → release to PyPI, npm, and Maven. Automated.
  • Unlimited local generation — validate a new API version before you ship it.
